# 架构与数据边界

操作步骤见[部署指南](../deploy/README.md)与 [Agent 指南](agent.md)，术语见[约定](conventions.md)。

## 数据流

```mermaid
flowchart LR
    A[Linux Agent] -->|注册与上报| S[服务器]
    S -->|流量确认| A
    S --> M[内存最新报告]
    S --> D[(orbitbeacon.db)]
    S -->|尽力写入| H[(metrics.db)]
    C[控制台] <-->|会话 API 与实时流| S
    S -->|白名单投影| P[状态页]
    S --> N[告警与通知]
    S --> B[加密备份]
```

- Agent 本地决定采集与探测参数；服务器只观察运行参数，不下发配置。
- 服务器按节点凭据识别节点，并用凭据代次、运行代次、会话和序号隔离旧进程及旧报告。
- 上报只保留最新普通样本，断网后不补历史；流量累计规则见 [Agent 指南](agent.md#流量累计)。
- 遥测忽略未知字段；已知字段仍校验，注册、恢复和管理写入拒绝未知字段。请求限制见[接口契约（OpenAPI）](../api/openapi.yaml)。

## 状态与历史

- **在线 / 离线**：服务器最近接收上报后 180 秒内为在线，超过才离线；依据服务器时间，不代表业务健康。状态页缺少有效运行身份、接收时间或时间异常时为未知；控制台另区分待注册、未上报及禁用状态。
- **已过期**：指标来源年龄超过 `max(3 × source_interval, 45s)`，或来源已标为 `stale`。浏览器断网只标记数据已过期，不自行判定节点离线。
- 封闭指令队列仅在上报身份围栏通过后的同一事务处理并审计；不纳入备份。最新的 stop 成功且下发时的 run_generation 仍是节点当前值时派生 stopped，抑制并恢复 offline 告警；任何新进程都会清除它。
- 完整最新报告只在内存中；重启后保留资产与已落库的 `last_seen`，数字须等待新报告。普通 `last_seen` 的持久化间隔为 30 秒加按节点 ID 哈希确定的固定偏移（不足 30 秒），到期后的下一次上报落库；首次上报及运行身份、system 或 runtime 变化仍立即持久化。
- 当前报告的有效 `ok` / `stale` 数字失联后保留；缺失、`error` 或 `unsupported` 显示不可用，不从旧报告拼补。数字及 uptime 不自行增长，心跳不刷新采样时间。
- 历史与告警只消费成功且新鲜的指标。历史缓冲有界、非阻塞，满时丢弃；历史库打开失败不阻止主服务，查询可能为空。
- 流量按进程 epoch 与 UTC 小时累计，同桶重复值取最大值；服务器确认已持久化或超过接收窗口的条目。账期按 UTC 月及 `billing_day` 计算，字节以十进制字符串返回；`billing_mode` 支持收发合计、较大值、仅接收或仅发送，`used_bytes` 为账期计费用量，各计数饱和至 int64 上限。配额不执行限速。
- `traffic_quota_percent` 每 tick 用一个读取快照批量合并日/小时计数，按各节点计费日计算，阈值为 (0,1000]，支持比较符及持续时间。离线不影响评估；读取失败不触发或恢复，配额清零或账期回落可恢复。本地关闭 traffic/network 阻止新告警，恢复须有新鲜报告。
- 探测按 `checked_at` 去重；当前目标尚无结果为 pending，移除目标清理旧观察，失联保留最近目标。24 小时可用率按 UTC 小时统计。
- 吊销或替换节点凭据清除运行身份、runtime、system、`last_seen` 和探测观察，保留资产及累计流量；同凭据幂等注册不清除。禁用节点保留凭据。

## 实时传输

- 状态页与控制台自动按 **WebSocket → SSE → HTTP** 回退。隐藏页面暂停，恢复可见后重连；控制台先复核会话。实时更新只修改只读数据，保留草稿、筛选和勾选。
- 控制台节点列表在在线状态后显示 CPU、内存两列，随舰队帧原位更新；不重载列表或改变筛选、排序和勾选。首次加载及服务器重启后，在新上报到达前显示占位符。舰队的 `cpu_percent`、`memory_used_percent` 为数字或 null，仅当前身份匹配、`presence=online` 且相应 `metric_status=ok` 时提供；内存复用 `100 * (total - available) / total`，总量为零或值缺失时为 null。摘要在接受上报时与原文一起发布，投影不解码报告；令牌视图和匿名状态页保持原契约。
- 首份快照立即返回，普通变化按[网页更新配置](../deploy/README.md#配置参考)合并；静默时每 10 秒心跳。`429` / `503` 的 `Retry-After` 会延后重试；持续变化可能返回 `503 snapshot_busy`。
- 200 节点容量测试使用 64 字符 Agent 版本、纳秒精度时区时间戳和长小数：舰队 JSON 从 47,514 增至 64,714 字节（+17,200），SSE 事件为 64,737 字节，低于浏览器 SSE 解析器的 1 MiB 上限；不改变广播节奏（默认 10 秒，可配置 2–60 秒）。
- WS/SSE 共用每 IP 4 条、全局 200 条与最长 15 分钟限制；私有流还受会话有效期约束。WS 要求可信 Origin，不接受应用写消息。
- 撤回公开、禁用或吊销/替换活跃凭据会要求流重建；已发送或离线保留的数据无法召回。

全站开关位于“设置 → 状态页 / Settings → Status page”，默认开启。`/` 与 `/public.html` 的 GET/HEAD 在 ETag 处理前执行下表规则，响应不缓存：

| 开关 | 匿名或无效会话 | 正常管理员会话 | 待改密会话 |
| --- | --- | --- | --- |
| 开启 | 状态页 | 状态页 | 状态页 |
| 关闭 | 302 `/login` | 302 `/overview` | 302 `/change-password` |

- 关闭后，`/api/public/v1/nodes`、`/api/public/v1/stream`、`/api/public/v1/ws` 返回 `403 public_page_disabled`；已有流尝试发送不含节点数据的同码错误帧后关闭。页面收到明确禁用信号才清空数据并返回 `/`；普通网络或服务错误只重试。
- 静态资源、Agent API、管理权限及节点公开白名单不受开关影响；重新开启不会发布私有节点。会话存储故障返回错误，不当作匿名访问。
- 开关持久化值损坏会拒绝启动；备份与恢复处理见[归档范围](../deploy/README.md#归档范围)。`/status` 不提供页面。

## 存储与保留

- 默认 SQLite：`orbitbeacon.db` 保存账户、资产、身份、设置、流量、探测、审计、告警、通知和备份任务，`metrics.db` 保存指标历史；使用 WAL、外键、`synchronous=FULL` 与 immediate 写事务。配置 MySQL primary 后，两个逻辑域分别使用该端点的业务和历史 database，不创建本地替代库。
- 业务与 SQL 历史分别持有稳定数据库句柄；请求从认证到响应固定同一世代，写 gate 串行化写事务，租约覆盖提交后内存发布。后台通知和备份固定认领、网络操作与结果保存的世代，但不持 SQL 事务等待网络。长连接只在每次认证、读取和发送时持租约，等待更新时释放。
- 租约取消会传入实际 SQL；排空须等待 Rows、Stmt、事务及驱动回滚真正结束，不能只等待 Go 调用返回。请求取消或期限到期不标记数据库故障；readiness 通过 guard 写探针解析待决提交、验证主库可提交后才恢复，liveness 不依赖数据库。
- `metrics.db` 保存标量和分盘使用率（字节及 inode）的分钟聚合及 rollup，不保存原始报告，无数据不补零。每节点最多 16 个不同分盘路径，同一路径的两个序列共享名额；超额的新路径样本丢弃并计入 `orbitbeacon_history_series_rejected_total`，已知路径和聚合继续写入。单 goroutine 管理路径集合和写入，节点首次出现时用读连接池的一条沿主键跳跃的查询在写事务外恢复路径集合；节点删除清理时释放集合，保留期过后不立即释放路径名额，重启按数据库实际内容重算。历史序列上限为 200 节点 × (17 个标量 + 16 路径 × 2) × 3 档精度 = 29,400（每条序列的桶数另受保留期限制）。`buckets.metric` 是普通文本，备份注册表按列原样备份和恢复，含 `:` 的分盘指标无需新增表或改注册表。格式兼容性见[升级](../deploy/README.md#升级)。
- MySQL 使用事务型 InnoDB。TCP 省略 `tls` 使用明文，仅限受控网络，凭据和数据不受传输加密保护；显式 `tls: {}` 启用 TLS 1.2+，默认校验系统根与 address 主机名，指定 CA 或 server_name 时按配置验证，失败不回退明文。本机 Unix socket 不接受 TLS。写事务先取得域内写 gate 和数据库 guard，COMMIT 结果未知时先冻结并核对事务 UUID，不能直接重做业务。单库模式不生成复制行日志。池指标读取当前域，MySQL 不报告遗留本地 SQLite WAL。
- MySQL 启动检查可写、事务型 InnoDB 与持久提交；启用 binlog 还要求同步刷盘及触发器部署条件，详见[数据库部署](../deploy/README.md#数据库)。开发地址和库名见[远程开发环境](../temp/README.md)。

| 数据 | 保留规则 |
| --- | --- |
| 指标历史 | 1 分钟粒度 48 小时；5 分钟粒度 14 天；1 小时粒度 90 天 |
| 流量 | 小时桶 35 天，完整过期日转日汇总；日汇总 400 天 |
| 探测小时统计 | 7 天 |
| 审计 / 已恢复告警 | 90 天；告警从恢复时间计算 |
| 通知投递 | 已发送或失败记录 30 天；pending 不按此规则删除 |
| 站内通知 | 创建后 90 天 |
| 终态任务 / 归档密码 | 完成后 90 天 |
| 手动导出文件 | 完成后 24 小时 |
| 注册票据 | 过期后额外保留 24 小时 |

服务器每小时分批清理，并处理过期会话；登录也会清理部分过期会话。已删除节点的历史可滞留至清理，查询先校验节点存在。计划包的保留由[备份目标](../deploy/README.md#备份目标)决定。

## 备份

- 仅备份已落库数据，不暂停采集或强制冲刷内存；两库分别一致，不保证跨库同一时刻。选择监控数据而历史库不可读时，任务失败。
- 恢复非监控归档时，缺失的本地历史只在私有恢复目录按空库准备；已存在但损坏的文件或孤立 sidecar 仍拒绝，不覆盖原数据。MySQL 先保存完整 old/new 私有镜像与 key，再持久化 prepared 决定、逐域替换；committed 前中断恢复全部旧状态，之后只完成新状态。数据库不可达时保留待决操作并拒绝服务，不打开半恢复系统。
- 按表/列白名单生成传输库，流式压缩加密，不落盘明文归档；恢复校验认证、清单、哈希、DDL 与行值。
- 全局最多 32 个非终态任务，单个 worker 执行；重启保留 queued，running 标为 `failed` / `interrupted`。存储结果未知时按[计划排障步骤](../deploy/README.md#计划)检查。
- 同一目录锁保护恢复；prepared journal 回滚旧文件组，committed journal 仅清理日志。操作和故障处理见[恢复](../deploy/README.md#恢复)。

## 告警与通知

- 启动及每 30 秒评估已注册、启用节点。缺失或过期指标重置等待计时，不证明恢复；离线规则无上报时从注册时间计算，最短阈值 180 秒。
- 磁盘取有效磁盘最大使用率；`probes_down` 无结果时为零。`probe_failed`、`probe_latency_ms`、`probe_tls_expiry_days` 只看规则指定的目标，无结果时算数据缺失，目标被 Agent 本地移除后恢复事件。恢复有滞回，等待计时在内存中，重启重置；已触发事件持久化，同规则/节点最多一个未恢复事件。
- 删除规则或作用域保留历史，未恢复事件在后续评估结束。未绑定通知通道仍生成告警事件和站内通知。
- 站内通知与告警变化或备份终态同事务提交，所有管理员共享，已读状态各自独立；来源过期后仍可看安全详情快照，未读数不等于当前触发数。备份结果只发站内通知。
- 外发支持 Webhook、Telegram、邮件、飞书、钉钉、企业微信、Bark、ntfy；pending 投递与告警事件、站内通知同事务提交，提交后唤醒 worker，持久化轮询兜底。临时失败最多尝试 5 次，退避 1、5、15、60 分钟；每通道每分钟 20 次，积压 100 条时合并后续通知。
- 外发可能延迟、重复或丢失：远端接收后状态未落库可重复；重试耗尽、不可重试的响应或通道禁用时放弃；洪泛合并只保留数量和最新详情。不能替代独立的高可靠告警系统。

## 安全

- 管理会话、注册票据与节点凭据互不通用；匿名 API 只读公开白名单。管理写入校验 Origin 与会话绑定 CSRF，登录校验 Origin；Cookie 与代理配置见[配置参考](../deploy/README.md#配置参考)。
- 所有账户均为等权管理员，至少保留一名。更名保留会话，删除撤销目标会话；新增管理员可要求首次改密，默认不勾选。会话有效期 12 小时。
- 待改密会话仅能查看本人会话、改密或退出，不影响匿名页与 Agent API。改密验证旧密码，拒绝相同新密码，原子撤销本人全部会话，必须重新登录；浏览器清除私有页面并阻止旧响应回写。离线时无法提前获知远端撤销。
- 没有密码找回或代改密；保留可用管理员，丢失密码时由另一管理员删除重建。初始化规则见[初始化凭据](../deploy/README.md#初始化凭据)。
- 节点默认不公开；仅已注册、启用、有有效节点凭据且显式公开的节点进入状态页。公开名称、地区和提供商独立配置，不从内部元数据回填；同时公开状态、CPU、内存、负载与 uptime，不公开完整报告。文本不自动脱敏，不要填写 IP、主机名、域名或秘密。
- Agent 主机失陷后，凭据和采集结果不再可信；信任根与运行身份由[安装策略](agent.md#手动前台安装)固定。探测配置的网络授权边界见[服务探测](agent.md#服务探测)。
- HTML 使用同源 CSP 并禁止嵌入框架，避免依赖第三方脚本或样式。
- 资产变更与审计同事务提交；批量操作逐节点提交并返回各自结果。通知凭据和完整 Webhook URL 由 `secrets.key` 派生密钥以 AES-256-GCM 加密，出站限制见[通知网络](../deploy/README.md#通知网络)。
- 正常关闭先标记不就绪、停止实时流，再限时关闭 HTTP 和后台任务、释放目录锁；强制终止可能丢失内存中的合并状态或历史。

## 容量参考

以下为单机实测（2026-11，fsync p50 25ms 的慢盘，每节点 2 磁盘、2 网卡、3 探测，10 秒上报，5 分钟）：

| 节点 | 上报分布 | 成功率 | 备注 |
|---|---|---|---|
| 200 | 均匀 | 100% | p95 35ms |
| 400 | 均匀 | 99.17% | 拒绝全部在首个 10 秒，之后为零 |
| 200 | 同步 | 96.62% | 拒绝主要在首 20 秒 |

首次上报必走持久写，服务器重启后全部节点会形成一次波峰，返回 `503 report_busy` 的 Agent 按 `Retry-After` 重试。这不是性能承诺，结果取决于磁盘。

## 开发压测

先在测试服务器创建批量注册票据（每张最多 100 次，30 分钟有效），逐行存入仓库外的文件。工具会真实注册节点并保留在服务器，不进入发布产物。

```sh
go run ./cmd/orbitbeacon-load -url http://127.0.0.1:8080 -tickets-file /path/to/tickets -nodes 200 -interval 10s -duration 5m -jitter 4900ms -disks 2 -networks 2 -probes 3
```

`-jitter` 决定节点的同步程度：接近间隔一半时近似均匀分布，较小时模拟同时上报。配置 `metrics_listen` 后，可从 `/metrics` 读取连接池、写队列、flush 和 WAL 指标。

同一独立监听的 `GET /metrics/nodes` 导出节点 gauge，支持 HEAD，无认证，主监听不提供该路径。每次抓取用两条批量 SELECT 读取清单身份及资产标签，不读取 notes；只有在线且凭据、凭据代次、运行代次和会话均通过与详情投影共用的身份围栏时才导出内存样本。离线、待注册或禁用节点只保留 info、up=0 和可用的 last_seen；重启后无内存样本时不补数字。

每个节点最多 3 条基础序列、9 条标量序列及每个磁盘 4 条、每个网卡 2 条序列；磁盘 inode 的 `orbitbeacon_node_disk_inodes_total{node_id,path}` 和 `orbitbeacon_node_disk_inodes_used{node_id,path}` 在数据为 null 时省略。协议分别限制最多 8 个磁盘和 8 个网卡，因此单次抓取最多每节点 60 条，节点数受 `max_nodes` 限制。标签变化会产生新时间序列，Prometheus 的历史基数还取决于保留期内资产、路径和网卡名的变化。

节点可用性由 `availability` 后台任务每 60 秒以单条原子 SQL 累计到主库 `node_availability_daily`（UTC 日），增量最多 90 秒，首次 tick 和时钟回拨只重设内存基线，启动 180 秒内只记在线。停机及未观测时长为未知，不进入百分比分母；保留任务分批保留最近 90 个 UTC 日。匿名页在现有缓存未命中路径用一次批量查询返回最近 30 天；公开 SSE/WebSocket 复用该完整页，控制台通过管理员可用性路由读取 30 或 90 天，前端共用时间条渲染器。

管理员丢失验证器和恢复码时，停服后运行 `orbitbeacon-server reset-totp --config /etc/orbitbeacon/server.json --username <name>`；也可沿用 `--data-dir <dir>` 的默认 SQLite 入口。目录锁阻止并发修改，只访问业务域，撤销目标用户全部会话与 API 令牌并记录系统审计。


### 只读 API 令牌

管理员通过 Cookie 会话和当前密码创建 `obt_` 令牌；创建事务重新验证发起会话和密码哈希，明文仅在创建响应返回一次，数据库仅存 SHA-256。令牌总数最多 20，过期项保留并占用名额。密码变更、在线或离线 TOTP 重置、删除用户会在同一事务撤销其全部令牌。

管理路由的 `Authorization` 以 `Bearer obt_` 开头时独立认证令牌，完全忽略 Cookie；其他 `Authorization`（如反向代理的 Basic 认证）不影响 Cookie 会话。`tokenRoutes` 独立白名单仅开放节点、样本、历史、可用率、流量、探测摘要、告警和分组读取；专用处理函数显式构造字段，排除备注、系统和运行设置、探测目标及错误。新增管理路由默认不开放，全部写操作、归档下载、审计和账户操作均拒绝。要求改密的所有者不能使用令牌。`last_used_at` 至多每五分钟尽力更新一次，无审计。API 令牌不进入备份，任意恢复后旧令牌失效。

每个令牌默认限额为每分钟 600 次请求，范围 1–100000；管理员可修改全局限额，或为单个令牌设置覆盖值（清空后使用全局值）。全局值无效时回退到 600。内存令牌桶容量等于限额，每秒补充限额的 1/60，重启后重置；修改限额后按新速率结算，不发放差额；认证成功后的禁止路由请求也计费。超限返回 429 `rate_limited`，`Retry-After` 为向上取整的等待秒数。全局限额随配置备份恢复；计数器 `orbitbeacon_api_token_rate_limited_total` 不带令牌标签。

Linux Agent 还采集物理整盘 IO 速率与最高忙碌率、PSI some avg60（CPU/内存/IO）及最热有效传感器温度。它们以可空字段和七条标量历史序列保存，不扩展 metric_status 或 sources；不支持或失败时省略测量。温度后台读取最多一个任务，每分钟刷新，超过三分钟的缓存丢弃。匿名状态页保持原有字段投影。
