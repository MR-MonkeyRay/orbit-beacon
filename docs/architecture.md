# OrbitBeacon 架构

OrbitBeacon 由中心 Server、Linux 非 root Agent 和 Server 内嵌网页组成。管理数据保存在本地 SQLite；不依赖外部数据库、消息队列或前端服务。

部署与备份见[部署说明](../deploy/README.md)，Agent 接入见 [Agent 文档](agent.md)，接口字段见 [OpenAPI](../api/openapi.yaml)。

## 组件与数据流

```text
Linux Agent ── HTTPS：注册 / 指标上报 ──> Server
    ^                                   ├─ ingest：最新快照（内存）
    └──────── 期望配置 / 流量确认 ────────┤    ├─ 合并持久化 ──> orbitbeacon.db
                                        │    └─ 尽力写入 ────> metrics.db
                                        ├─ 告警评估 ──> 事件 / 通知投递
                                        ├─ 管理 API <── 管理会话
                                        └─ 公开投影 ──> 匿名 API / SSE
```

- **Agent**：`cmd/orbitbeacon-agent` 校验安装策略及运行账户；`internal/agent/collect` 采集指标，`probe` 执行服务探测，`service` 管理注册、配置及上报，`identity` 持久化安装身份和凭据。
- **Server**：`cmd/orbitbeacon-server` 锁定数据目录，打开数据库并启动 HTTP、可选 metrics listener、告警、通知与保留清理任务。`internal/server` 负责路由、鉴权边界及响应投影；业务分别位于 `auth`、`nodes`、`enrollment`、`ingest`、`alerts`、`notify` 等包。
- **网页**：`web/src` 构建为 `internal/server/webui/dist`，通过 Go `embed` 打包。`/` 是中文公开页，`/login` 等路由是英文管理控制台；运行 Server 不需要 Node.js。

## 采集、上报与配置

Agent 维护一个采集循环和一个上报 worker，每次采集最多 3 秒。普通指标不保存离线队列：请求或退避期间的新采样覆盖旧快照，恢复后发送最新数据。累计流量在进程内保留最多 24 个小时桶并重发未确认值；重启或超出容量时可能丢失。

Server 在读取报告正文前检查 bearer 凭据，再校验协议、节点状态和运行身份。`run_generation` 与 `session_id` 阻止旧进程继续上报，`seq` 用于当前 Server 进程内去重；禁用节点、撤销凭据和冲突身份均不能继续更新状态。

远端配置以期望版本与已应用版本协调，Agent 在采集器实际采用配置后才确认版本。配置范围是采集周期、网卡、磁盘路径、探测目标及流量账期/配额；当前 Agent 声明 `self_update=false`，没有远程升级、终端、任意命令或文件管理功能。

### 最新状态与持久化

- 最新完整报告、接收时间和公开指标快照保存在内存；`GET /api/v1/nodes/{id}/latest` 不是历史查询，Server 重启后须等待新报告。读取时重新核对数据库中的凭据、代次和会话，避免返回旧身份数据。
- 普通连续报告可只更新内存，`last_seen` 默认约每 30 秒持久化。新运行/会话、系统信息或配置状态变化等会触发立即写入；SQLite 写入使用有界队列和单写者槽，拥塞时返回忙响应。
- 在线状态按服务器接收时间判断，共用 180 秒窗口，不依赖 Agent 墙上时钟。在线不等于每项指标都新鲜；公开投影和告警还检查指标来源状态及采样年龄。

### 流量与服务探测

流量按 Agent 进程 `epoch` 和 UTC 小时累计。同一桶重复上报取最大值，随合并事务或关闭排空写入主库；只确认已持久化值，以及已超出 35 天窗口而被丢弃的条目。流量 API 合并小时数据与每日汇总，按 `billing_day` 计算 UTC 月度账期，字节计数用十进制字符串返回。配额是统计信息，不执行网络限速。

服务探测由 Agent 发起，每节点最多 5 个目标，默认每 60 秒检查一次、单次最多 5 秒。结果随报告提交并合并持久化，以检查时间去重；缓冲满时返回忙响应而非静默丢弃。`GET /api/v1/nodes/{id}/probes` 只返回当前配置的目标，因此可能比上报滞后约 30 秒。24 小时可用率按 UTC 小时桶统计，不是精确滚动窗口。

## SQLite 与数据保留

主库 `orbitbeacon.db` 保存账户、节点、注册票据、配置、身份栅栏、审计、流量、探测、告警和通知投递。使用纯 Go SQLite 驱动、WAL、外键、5 秒 busy timeout、`synchronous=FULL` 与 immediate 写事务。迁移和版本记录一并提交；主库版本高于二进制支持版本时拒绝启动。公开查询使用迁移后打开的独立只读连接池。

当前主库迁移版本为 16，增加备份计划、备份任务、站内通知和用户已读状态；历史任务不随计划或操作人删除而级联删除，已读状态随用户或通知删除。升级后的主库不能由旧版二进制打开。

`metrics.db` 是独立的尽力而为指标历史库，不保存原始报告。成功且新鲜的标量样本经有界非阻塞缓冲交给单 writer，约每分钟写入分钟聚合及加权 rollup；无数据不补零，缓冲或待写桶满时丢弃并计数。该库打开失败只记录警告，主服务继续运行，历史接口返回空点集。

| 数据 | 保留规则 |
| --- | --- |
| 指标历史 | 1 分钟粒度 48 小时；5 分钟粒度 14 天；1 小时粒度 90 天 |
| 流量 | 小时桶 35 天；完整过期日转为日汇总，日汇总保留 400 天 |
| 服务探测 | 最新结果及小时统计；小时统计保留 7 天 |
| 审计 / 已恢复告警 | 90 天；告警从恢复时间计算 |
| 通知投递 | 已发送或失败记录 30 天；pending 不按此规则删除 |
| 注册票据 | 过期后额外保留 24 小时 |

保留任务每小时执行，分批清理并处理过期会话。节点删除后的指标历史可能保留至下一轮清理，但历史 API 始终先验证节点存在。

离线 `restore` 只接受新版加密包，按类别整体替换，未含类别保留；不接收旧裸 SQLite。恢复在持锁状态下先验证归档和最终依赖，再以 prepared/committed journal 安装主库、指标库和密钥；未完成安装回滚为完整旧文件组，原始副本保留供诊断。恢复配置会停用计划、丢弃旧会话和票据；恢复事件不重放任务或外发投递。

`internal/server/backup` 的新版归档协议为 `.tar.gz.age`：配置、监控、事件独立选择；仅配置类别带匹配的 `secrets.key`。主库及指标库分别取只读一致快照，再按固定表/列白名单创建新传输库，避免未选数据留在 freelist。每包独立生成 16 位随机密码；流式压缩加密，恢复先验证完整认证、清单、哈希、结构及行值。版本必须精确匹配，不执行包内 DDL，不承诺两库同一快照时刻。

## 告警与通知

告警启动时评估一次，之后每 30 秒评估已注册且启用的节点。指标规则使用身份匹配且新鲜的最新报告；缺失或过期指标会重置等待计时，但不证明恢复。磁盘告警取有效磁盘中的最大使用率；`probes_down` 统计最新报告中的失败目标数，没有结果时为零。离线规则使用最近接收时间，尚未上报则回退到注册时间，最短离线阈值为 180 秒。

恢复使用滞回以减少阈值附近反复触发。等待计时只在内存，重启后重置；已触发事件在数据库中保留，重启不会重复创建。同一规则/节点最多有一个未恢复事件。删除规则或作用域不会删除已有事件历史，未恢复事件在后续评估中结束。

事件提交后，通知先进入有界内存队列，再为规则绑定的启用通道创建持久 pending 投递。支持 Webhook、Telegram 和邮件；发送与评估事务分离。临时失败最多尝试 5 次，退避为 1、5、15、60 分钟；每通道限制 20 次/分钟，积压达到 100 条时合并后续通知。

持久投递重启后继续，但不保证恰好一次：远端接受后、状态落库前崩溃可能重复；事件提交后、入库投递前崩溃或内存队列满仍可能丢失通知。

## 认证与安全边界

- **主机与 Agent**：安装策略固定服务器地址、状态目录和运行身份；运行时拒绝 root 或不匹配的 UID/GID/账户。主机失陷后，凭据和采集结果不再可信。探测请求来自 Agent 所在网络，应将探测配置视为对其网络访问的授权。
- **Agent 与 Server**：只使用 HTTPS；服务器由凭据映射节点，不信任报告自述的身份、顺序或状态。凭据不授予管理 API 权限。
- **浏览器与管理 API**：仅使用 Secure、HttpOnly 会话 cookie；管理写入要求管理员、可信 Origin 和会话绑定的 CSRF，退出与修改本人密码另按会话权限处理。应审计的管理变更与审计事件在同一事务提交。
- **公开数据**：默认不发布，公开名称、地区和提供商独立配置，不从内部元数据回填。匿名响应只含公开字段、状态及 CPU/内存/负载/运行时间白名单，不返回节点内部记录或完整报告。
- **本地数据**：数据目录、数据库和密钥是 Server 信任根，打开前检查路径、所有权和权限；禁止多个 Server 同时使用同一数据目录。
- **目录原语**：`datadir` 统一持有不删除的 `server.lock`，校验主库、指标库及 sidecar 的所有者、权限和无符号链接；启动可创建密钥，恢复预检仅检查元数据，不创建或解析业务文件。
- **通知密钥与出站**：通道凭据和完整 Webhook URL 用 `secrets.key` 派生的 AES-256-GCM 密钥加密，密文绑定通道身份；读取 API 不返回明文。默认拒绝私网、回环及元数据目标，拨号前解析并直接连接检查过的 IP；HTTP 不使用代理、不跟随重定向。SMTP 要求 STARTTLS 或 465 隐式 TLS。放宽出站策略的开关及风险见部署说明，元数据地址始终禁止。
- **反向代理**：只有配置的可信代理可提供转发客户端地址；TLS 可由 Server 或前置代理终止，对外仍须使用 HTTPS。

## 公开更新与关闭

公开查询仅选择显式发布、已注册、有凭据且未禁用的节点。公开分页缓存 2 秒；发布设置、启停、删除或注册身份变化提交后递增可见性版本，使旧缓存失效。内存指标仍须与持久身份匹配。

`/api/public/v1/stream` 使用与分页 API 相同的投影，首帧立即发送，变化帧最多每 2 秒一次，无变化时约每 10 秒发送。每 IP 最多 4 条、全局最多 200 条流，连接最长 15 分钟；到期或关闭时发送 `close` 事件。公开页优先 SSE，建流失败时降级为每 10 秒轮询；反向代理须关闭流缓冲。

收到 `SIGINT`/`SIGTERM` 或 HTTP 服务退出后，Server 取消根 context、标记 readiness 不可用并关闭公开流。在共享的 10 秒期限内关闭 HTTP listener 并等待 handler，然后分别给 ingest 排空、通知停止最多 5 秒；等待告警、通知和保留任务退出后，再给历史队列刷新最多 5 秒，最后关闭数据库并释放目录锁。HTTP 关闭超时会强制断开连接，ingest、通知或历史排空超时会记录告警；强制终止不能保证内存中的合并状态和历史已写入。
