# OrbitBeacon 架构

OrbitBeacon 由中心 Server、Linux 非 root Agent 和 Server 内嵌网页组成。管理数据保存在本地 SQLite；不依赖外部数据库、消息队列或前端服务。

部署与备份见[部署说明](../deploy/README.md)，Agent 接入见 [Agent 文档](agent.md)，接口字段见 [OpenAPI](../api/openapi.yaml)。

## 组件与数据流

```text
Linux Agent ── HTTPS：注册 / 指标上报 ──> Server
    ^                                   ├─ ingest：最新快照（内存）
    └──────── 期望配置 / 流量确认 ────────┤    ├─ 合并持久化 ──> orbitbeacon.db
                                        │    └─ 尽力写入 ────> metrics.db
                                        ├─ 告警评估 ──> 事件 / 站内通知 / 外发投递
                                        ├─ 备份计划 / 手动导出 ──> 加密归档 / 站内通知
                                        ├─ 管理 API <── 管理会话
                                        └─ 公开投影 ──> 匿名 API / SSE
```

- **Agent**：`cmd/orbitbeacon-agent` 校验安装策略及运行账户；`internal/agent/collect` 采集指标，`probe` 执行服务探测，`service` 管理注册、配置及上报，`identity` 持久化安装身份和凭据。
- **Server**：`cmd/orbitbeacon-server` 锁定数据目录，先收敛未完成恢复，再打开数据库并启动 HTTP、可选 metrics listener、告警、通知、备份与保留清理任务。`internal/server` 负责路由、鉴权边界及响应投影；业务分别位于 `auth`、`nodes`、`enrollment`、`ingest`、`alerts`、`notify`、`inbox`、`backup` 等包。
- **网页**：`web/src` 构建为 `internal/server/webui/dist`，通过 Go `embed` 打包。`/` 是中文公开页，`/login` 等路由是英文管理控制台；运行 Server 不需要 Node.js。

## 采集、上报与配置

Agent 维护一个采集循环和一个上报 worker，每次采集最多 3 秒。普通指标不保存离线队列：请求或退避期间的新采样覆盖旧快照，恢复后发送最新数据。累计流量在进程内保留最多 24 个小时桶并重发未确认值；重启或超出容量时可能丢失。

Server 在读取报告正文前检查 bearer 凭据，再校验协议、节点状态和运行身份。`run_generation` 与 `session_id` 阻止旧进程继续上报，`seq` 用于当前 Server 进程内去重；禁用节点、撤销凭据和冲突身份均不能继续更新状态。

远端配置以期望版本与已应用版本协调，Agent 在采集器实际采用配置后才确认版本。配置范围是采集周期、网卡、磁盘路径、探测目标及流量账期/配额；当前 Agent 声明 `self_update=false`，没有远程升级、终端、任意命令或文件管理功能。

### 最新状态与持久化

- 最新完整报告、接收时间和公开指标快照保存在内存；`GET /api/v1/nodes/{id}/latest` 不是历史查询，Server 重启后须等待新报告。读取时重新核对数据库中的凭据、代次和会话，避免返回旧身份数据。
- 普通连续报告可只更新内存，`last_seen` 默认约每 30 秒持久化。新运行/会话、系统信息或配置状态变化等会触发立即写入；SQLite 写入使用有界队列和单写者槽，拥塞时返回忙响应。
- 在线状态按服务器接收时间判断，共用 180 秒窗口，不依赖 Agent 墙上时钟。在线不等于每项指标都新鲜；公开投影和告警还检查指标来源状态及采样年龄。

### 流量与服务探测

流量按 Agent 进程 `epoch` 和 UTC 小时累计。同一桶重复上报取最大值，随合并事务或关闭排空写入主库；只确认已持久化值，以及已超出 35 天窗口而被丢弃的条目。流量 API 合并小时数据与每日汇总，按 `billing_day` 计算 UTC 月度账期，字节计数用十进制字符串返回。配额是统计信息，不执行网络限速。

服务探测由 Agent 发起，每节点最多 5 个目标，默认每 60 秒检查一次、单次最多 5 秒。结果随报告提交并合并持久化，以检查时间去重；缓冲满时返回忙响应而非静默丢弃。`GET /api/v1/nodes/{id}/probes` 只返回当前配置的目标，因此可能比上报滞后约 30 秒。24 小时可用率按 UTC 小时桶统计，不是精确滚动窗口。

## SQLite 与数据保留

主库 `orbitbeacon.db` 保存账户、节点、注册票据、配置、身份栅栏、审计、流量、探测、告警、通知投递及备份任务。使用纯 Go SQLite 驱动、WAL、外键、5 秒 busy timeout、`synchronous=FULL` 与 immediate 写事务。空库在一个事务中直接创建当前完整结构及单行版本记录，不执行历史迁移；公开查询使用初始化成功后打开的独立只读连接池。

当前主库 schema 为 18。已有库必须恰好含一条当前版本记录；旧 schema 16/17、缺少/空/混合版本记录和更高版本库均拒绝，拒绝时不改业务数据或版本记录、不自动删除文件。需要新格式时使用新的私有数据目录，不提供旧库转换。账户仅保留等权管理员，账户表不存权限字段，站内通知不分受众。历史任务不随计划或操作人删除而级联删除，已读状态随账户或通知删除。

已读记录按账户隔离；`inbox_reads.notification_id` 独立索引支持通知过期时的外键级联清理，避免逐条扫描全部已读记录。

`metrics.db` 是独立的尽力而为指标历史库，不保存原始报告。成功且新鲜的标量样本经有界非阻塞缓冲交给单 writer，约每分钟写入分钟聚合及加权 rollup；无数据不补零，缓冲或待写桶满时丢弃并计数。该库打开失败只记录警告，主服务继续运行，历史接口返回空点集。

指标库仍独立使用 schema 1 及原有 SQL 初始化/迁移机制，不随主库格式切换改变。

| 数据 | 保留规则 |
| --- | --- |
| 指标历史 | 1 分钟粒度 48 小时；5 分钟粒度 14 天；1 小时粒度 90 天 |
| 流量 | 小时桶 35 天；完整过期日转为日汇总，日汇总保留 400 天 |
| 服务探测 | 最新结果及小时统计；小时统计保留 7 天 |
| 审计 / 已恢复告警 | 90 天；告警从恢复时间计算 |
| 通知投递 | 已发送或失败记录 30 天；pending 不按此规则删除 |
| 站内通知 / 任务 / 归档密码 | 通知创建后 90 天；终态任务及密码从任务完成后计 90 天，活动任务密码不清理 |
| 手动导出文件 | 任务完成后 24 小时；计划本地包按份数、远程包按云端生命周期保留 |
| 注册票据 | 过期后额外保留 24 小时 |

保留任务每小时执行，分批清理并处理过期会话。节点删除后的指标历史可能保留至下一轮清理，但历史 API 始终先验证节点存在。

## 加密归档与恢复

管理员通过 Settings → Data operations 发起导出、管理计划和查看任务；没有备份 CLI 或网页上传恢复。离线 `restore --data-dir PATH --input ARCHIVE [--replace] [--password-file FILE]` 只接受新版加密包，按类别整体替换，未含类别保留，不逐条合并；缺失稳定 ID 依赖整次拒绝，不按名称匹配或创建节点。已有业务数据须显式 `--replace`，空目标须包含配置。密码由终端无回显输入，或从运行用户所有的 `0600` 普通文件读取，不通过参数或环境变量传入明文。

`internal/server/backup` 的归档协议为 `.tar.gz.age`：configuration、monitoring、events 独立选择、至少一类，默认仅配置。仅配置类别带匹配的 `secrets.key`，包含密码哈希、Agent 身份及加密凭据，但不含部署配置、TLS 证书或程序。事件不带历史备份密码；会话、接入票据、待执行任务、待发送通知和旧产物永不归档。主库及指标库分别取只读一致快照，再按固定表/列白名单创建新传输库，避免未选数据留在 freelist。只取已落库数据，不暂停采集或额外冲刷；选择监控时历史库不可读则失败，不保证跨库同一时刻。

每包独立生成 16 位随机大小写字母/数字密码，流式压缩加密，不落盘明文 tar.gz。恢复先验证完整认证、清单、哈希、结构及行值；当前归档格式为 v1，要求主库 schema 18、指标库 schema 1 精确匹配，旧 schema 16/17 包即使仅含 Monitoring 也拒绝。传输表定义须等于固定 registry DDL，在完整性检查前拒绝额外 CHECK、collation 等表达式，不执行包内 DDL，不接受裸 SQLite、旧格式转换或跨 schema 转换。持同一锁以 prepared/committed journal 安装主库、指标库和密钥，data-dir 与锁 inode 不变；prepared 安全回滚完整旧文件组，committed 仅清 journal。`.restore-<id>/old/` 原始副本不自动删除，损坏副本或无效 journal 会阻止启动。恢复配置会停用所有计划、丢弃旧会话和票据；恢复事件不重放任务或外发投递，保留目标事件时原活动工作标为恢复中断。恢复后按真实状态评估告警，不伪造在线或增加静默期。

导出任务持久排队，全局最多 32 个非终态任务、一个 worker；网页受理事务与后台执行解耦。阶段为 snapshot、packaging、storing，无估算百分比。发布前持久保存密码密文及完整位置/哈希；发布成功后只重试终态与站内通知的同一事务，不重复压缩或上传。重启保留 queued，running 转 failed/interrupted；存储阶段中断明确标记结果未知。

手动产物只位于私有 `exports/<task-id>/`，完成后有效 24 小时，使用受会话保护的附件下载，不自动下载；计划包不另建网页下载副本。密码与任务保留至完成后 90 天，密码只能显式请求且不会随远程包上传；没有主密码托管，原机丢失或密码过期且未另存则无法恢复。清理只操作自有 UUID 文件，失败时保留最小定位记录并延后重试；归档导入的历史任务不取得下载文件或外部路径的清理权。

备份计划使用五段 Cron，默认 `0 3 * * *`、新建停用；时区在进程启动时固定为 Server 的 `time.Local`，不是浏览器时区。预览返回每次执行的真实当地时间与 offset，修改机器时区须重启，容器不假定继承宿主时区。持久 `next_run_at` 配合一个 timer 和合并唤醒通道；错过多个周期只补一次，计划活动或队列满时保留 due，不累计任务。活动计划不可编辑、停用或删除，删除计划不删除已保存归档。

每条计划仅一个本地或对象存储目标。本地目录须预先由服务用户所有、`0700`、无符号链接且可写，默认保留最近 7 份，成功后按份数清理自己的归档；systemd 自定义路径用精确 `ReadWritePaths` drop-in，Compose 用卷或额外挂载，不放宽根文件系统。COS、OSS、R2、AWS S3 与 S3-compatible 统一使用一套 S3 SDK 和静态凭据，不使用主机默认凭据链；HTTPS ≥ TLS 1.2、校验证书、无代理/重定向，安全 DNS 拨号覆盖最终 bucket 域名，私网 opt-in 仍不允许回环、链路本地、非全局单播或元数据地址。远程只上传，保留由云生命周期管理。已进行 profile 协议测试和真实 MinIO smoke，四家实云未实测；配置细节见部署说明。

## 告警与通知

告警启动时评估一次，之后每 30 秒评估已注册且启用的节点。指标规则使用身份匹配且新鲜的最新报告；缺失或过期指标会重置等待计时，但不证明恢复。磁盘告警取有效磁盘中的最大使用率；`probes_down` 统计最新报告中的失败目标数，没有结果时为零。离线规则使用最近接收时间，尚未上报则回退到注册时间，最短离线阈值为 180 秒。

恢复使用滞回以减少阈值附近反复触发。等待计时只在内存，重启后重置；已触发事件在数据库中保留，重启不会重复创建。同一规则/节点最多有一个未恢复事件。删除规则或作用域不会删除已有事件历史，未恢复事件在后续评估中结束。

站内通知与告警 firing/resolved 或备份终态在同一事务提交，外发通道或其队列不可用不影响站内记录；备份结果不外发。所有管理员共享任务结果、下载和密码，铃铛同时包含备份与告警；已读状态逐账户保存，未读数不等于当前 firing 数。read-all 用本库新增 sequence 对应的 UUID 水位，不按时间或 UUID 字典顺序推断新旧。通知保留不可变安全详情，源任务或告警过期后仍可阅读通知快照。

站内快照写入和归档恢复共用无副作用的字段形状校验；拒绝会破坏消费者的类别、嵌套目标、时间和数值类型，保留合法的稀疏历史快照与未知字符串元数据，不回查或重建已删除来源。

告警事件提交后，外发通知先进入有界内存队列，再为规则绑定的启用通道创建持久 pending 投递。支持 Webhook、Telegram 和邮件；发送与评估事务分离。临时失败最多尝试 5 次，退避为 1、5、15、60 分钟；每通道限制 20 次/分钟，积压达到 100 条时合并后续通知。

持久投递重启后继续，但不保证恰好一次：远端接受后、状态落库前崩溃可能重复；事件提交后、入库投递前崩溃或内存队列满仍可能丢失通知。

## 认证与安全边界

- **主机与 Agent**：安装策略固定服务器地址、状态目录和运行身份；运行时拒绝 root 或不匹配的 UID/GID/账户。主机失陷后，凭据和采集结果不再可信。探测请求来自 Agent 所在网络，应将探测配置视为对其网络访问的授权。
- **Agent 与 Server**：只使用 HTTPS；服务器由凭据映射节点，不信任报告自述的身份、顺序或状态。凭据不授予管理 API 权限。
- **浏览器与管理 API**：仅使用 Secure、HttpOnly 会话 cookie；全部账户均为等权管理员，管理写入要求可信 Origin 和会话绑定的 CSRF，应审计的管理变更与审计事件在同一事务提交。可新增、更名和删除管理员；更名保留会话，删除立即撤销目标全部会话，末位管理员不能删除，有其他管理员时可自删。仅支持验证旧密码后修改本人密码，并撤销本人全部会话；不提供代改密、重置或找回流程。用户名按 1–128 个 UTF-8 字节精确匹配，不裁剪或折叠大小写；密码为 8–1024 个 UTF-8 字节。
- **公开数据**：默认不发布，公开名称、地区和提供商独立配置，不从内部元数据回填。匿名响应只含公开字段、状态及 CPU/内存/负载/运行时间白名单，不返回节点内部记录或完整报告。
- **本地数据**：数据目录、数据库和密钥是 Server 信任根，打开前检查路径、所有权和权限；禁止多个 Server 同时使用同一数据目录。
- **目录原语**：`datadir` 统一持有不删除的 `server.lock`，校验主库、指标库及 sidecar 的所有者、权限和无符号链接；启动可创建密钥，恢复预检仅检查元数据，不创建或解析业务文件。
- **通知密钥与出站**：通道凭据和完整 Webhook URL 用 `secrets.key` 派生的 AES-256-GCM 密钥加密，密文绑定通道身份；读取 API 不返回明文。默认拒绝私网、回环及元数据目标，拨号前解析并直接连接检查过的 IP；HTTP 不使用代理、不跟随重定向。SMTP 要求 STARTTLS 或 465 隐式 TLS。放宽出站策略的开关及风险见部署说明，元数据地址始终禁止。
- **反向代理**：只有配置的可信代理可提供转发客户端地址；TLS 可由 Server 或前置代理终止，对外仍须使用 HTTPS。

## 公开更新与关闭

公开查询仅选择显式发布、已注册、有凭据且未禁用的节点。公开分页缓存 2 秒；发布设置、启停、删除或注册身份变化提交后递增可见性版本，使旧缓存失效。内存指标仍须与持久身份匹配。

`/api/public/v1/stream` 使用与分页 API 相同的投影，首帧立即发送，变化帧最多每 2 秒一次，无变化时约每 10 秒发送。每 IP 最多 4 条、全局最多 200 条流，连接最长 15 分钟；到期或关闭时发送 `close` 事件。公开页优先 SSE，建流失败时降级为每 10 秒轮询；反向代理须关闭流缓冲。

收到 `SIGINT`/`SIGTERM` 或 HTTP 服务退出后，Server 取消根 context、标记 readiness 不可用并关闭公开流。在共享的 10 秒期限内关闭 HTTP listener 并等待 handler，然后分别给 ingest 排空、通知停止最多 5 秒；等待告警、通知、备份和保留任务退出后，再给历史队列刷新最多 5 秒，最后关闭数据库并释放目录锁。HTTP 关闭超时会强制断开连接，ingest、通知或历史排空超时会记录告警；强制终止不能保证内存中的合并状态和历史已写入。
