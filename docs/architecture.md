### 数据边界要点

- **配置归属**：采集间隔、网卡、磁盘、探测目标与远程指令许可仅保存于 Agent 本地；Server 通过 `node_token`、`credential_epoch`、`run_generation`、`report_session_id` 和 `seq` 隔离旧进程与旧报告。
- **不补历史**：Agent 断网期间只保留最新普通样本，恢复后不补历史；流量除外（按进程 `epoch` + UTC 小时累计，见 [Agent 指南](agent.md#41-流量累计与服务器-ack)）。
- **容错解耦**：普通指标写入有界非阻塞缓冲，满时丢弃；历史库故障不影响主库接收入站上报，仅历史查询与含 Monitoring 的备份受影响。
- **字段校验**：遥测允许忽略未知字段（仍校验已知字段）；注册、恢复和管理接口严格拒绝未知字段（契约见 [openapi.yaml](../api/openapi.yaml)）。

## 3. 节点状态、指标新鲜度与可用率

### 3.1 节点状态机

```text
[创建节点] ──▶ pending (待注册)
                 │
                 │ 首次使用一次性密钥注册 (enroll)
                 ▼
             never_seen (未上报)
                 │
                 │ 收到首份合法 report
                 ▼
             +--------+   超过 180s 未收到上报    +---------+
             | online | -----------------------> | offline |
             +---+----+ <----------------------- +----+----+
                 |         收到新合法 report           ^
                 |                                    |
     收到 stop 指令回执且                   任何新进程上报    |
     run_generation 未变                  (run_generation 变更)
                 |                                    |
                 v                                    |
             +---------+ -----------------------------+
             | stopped | (派生状态: 抑制 offline 告警并触发恢复)
             +---------+

  * 管理员禁用节点 ──▶ disabled (保留凭据，拒绝上报)
  * 吊销/替换凭据  ──▶ 清除运行身份、system、last_seen、探测观测 (保留资产与累计流量)
```

> **公开状态页补充**：当有效运行身份、接收时间缺失或时间异常时，状态页显示 `unknown`。

### 3.2 指标新鲜度与可用性

- **已过期（`stale`）**：指标年龄超过 `max(3 × source_interval, 45s)`，或来源本身标记为 `stale`。浏览器断网仅在本地标为过期，不自行改判节点离线。
- **缺省规则**：有效 `ok` / `stale` 数字在失联后保留，但不自增、也不由心跳刷新采样时间；缺失 / `error` / `unsupported` 均显示不可用，绝不从历史拼补。
- **last_seen 落库节流**：完整报告仅驻留内存（重启后需等待新上报）；普通上报每隔 `30s + hash(node_id)`（不足 30s 的分散偏移）落库一次 `last_seen`，首次上报、运行身份或 `system` 变更立即落库。
- **可用率统计（`availability`）**：每 60 秒在写事务内批量（每批 ≤ 500 节点，单次增量 ≤ 90 秒）统计在线时长写入 `node_availability_daily`（UTC 日，保留 90 天）。停机与未观测时段计为未知，**不计入百分比分母**；服务端启动后前 180 秒仅累计在线时长。

## 4. 服务端服务监控（`services`）

独立于 Agent 本地探测，由 Server 主动探测最多 100 项 HTTP / TCP / ICMP（Linux 无特权 datagram ping socket）服务。

```text
+-----------------+   ±10% 抖动调度    +--------------------+   egress.Dialer   +----------+
| 1 Scheduler     | ----------------> | 8 Probe Workers    | ----------------> | 目标端点  |
| (单服务不重叠)   |                   | (HTTP / TCP / ICMP)| (允许私网, 禁IMDS) |          |
+-----------------+                   +---------+----------+                   +----------+
                                                |
                   +----------------------------+----------------------------+
                   v                                                         v
     +---------------------------+                             +---------------------------+
     | 状态机 (同事务写库与通知)   |                             | 10s 批量落库与 5m 聚合桶    |
     |  - 连续 2 次失败 -> down   |                             |  - service_checks_latest  |
     |  - 1 次成功      -> up     |                             |  - service_check_buckets  |
     |  - 连续 3 次高延迟 -> 告警 |                             |    (历史库保留 30 天)       |
     |  - 证书<=14天    -> 每日1次|                             +---------------------------+
     +---------------------------+
```

- **不可达与公开边界**：若配置、目标、类型或延迟阈值变更则重置状态机（保留历史）；结果超过 `2 × interval + timeout` 变 `unknown`。公开页仅输出 `enabled && public` 的名称、类型、状态、延迟与 30 天按成功样本计算的可用率，不含目标地址或原始错误。

## 5. 实时传输与页面网关分流

### 5.1 WebSocket → SSE → HTTP 回退时序

控制台与状态页均复用 `web/src/shared/live.js` 自动降级；页面隐藏时暂停通道，恢复可见时重新连接（控制台先复核会话）。

```text
浏览器 (Browser)                                   服务端 (Server)
   │                                                     │
   ├── 1. 建立 WebSocket (/ws) ─────────────────────────▶│  [正常] 立即推首份快照
   │◀─ snapshot + 合并增量 / 每 10s heartbeat ────────────┤         并按周期合并推送
   │                                                     │
   │   [WS 失败或 8s 未收到首份快照]                       │
   ├── 2. 降级 SSE (/stream) ───────────────────────────▶│
   │◀─ snapshot + events ────────────────────────────────┤  (后台每 5 分钟尝试恢复 WS)
   │                                                     │
   │   [SSE 失败或 8s 未收到首份快照]                      │
   ├── 3. 兜底 HTTP 轮询 ───────────────────────────────▶│
   │◀─ JSON snapshot ────────────────────────────────────┤  (429/503 按 Retry-After 退避)
   │                                                     │
   │   [收到 403 public_page_disabled 或同名控制帧]        │
   └── 清空本地节点/服务/图形缓存并 location.replace('/') ◀┤  (流重建触发: 撤回公开/禁用/改组)
```

- **连接限额**：WS 与 SSE 共用限额 —— **每 IP ≤ 4 条、全局 ≤ 200 条、单条最长 15 分钟**；WS 严格校验可信 `Origin` 且不接受应用层写消息。
- **节点列表原位更新**：控制台列表在在线状态后显示 CPU / 内存两列，随实时帧原位更新，不重排列表、不重置筛选和勾选；仅在身份匹配、`presence=online` 且 `metric_status=ok` 时显示数字。

### 5.2 状态页网关分流（`GET/HEAD /` 与 `/public.html`）

由 `设置 → 状态页` 全局开关控制（默认开启，可同时配置 `show_groups` 是否公开分组），响应不缓存：

| 全局开关 | 匿名 / 无效会话 | 正常管理员会话 | 待改密会话 |
| --- | --- | --- | --- |
| **开启** | 返回公开状态页 | 返回公开状态页 | 返回公开状态页 |
| **关闭** | `302 /login` | `302 /overview` | `302 /change-password` |

- **公开分组展示**：开启 `show_groups` 后，快照返回包含公开成员的 `node_groups` / `service_groups` 名称数组及成员索引 `group`（未分组为 `null`）；私有组名、组 ID 与成员总数永不外泄。

## 6. 安全边界、凭据隔离与只读 API 令牌

### 6.1 四类凭据互不通用

```text
+-----------------------+-----------------------------------+------------------------------+
| 凭据类型               | 承载方式                           | 权限与生命周期                |
+-----------------------+-----------------------------------+------------------------------+
| 管理员会话             | Cookie (orbitbeacon_session)       | 12h 有效; 写操作校验 Origin   |
|                       | + 会话绑定 CSRF Token              | 与 CSRF; 改密原子撤销全会话    |
+-----------------------+-----------------------------------+------------------------------+
| 只读 API 令牌          | Authorization: Bearer obt_<...>   | 最多 20 个; 仅 DB 存 SHA-256  |
|                       | (仅管理路由读白名单)                | 忽略 Cookie; 令牌桶限流       |
+-----------------------+-----------------------------------+------------------------------+
| 一次性注册密钥         | HTTPS Body / 安装脚本交互输入       | 32B base64url; 30m 有效;      |
|                       |                                   | 仅 1 次成功激活; 失效受限流保护|
+-----------------------+-----------------------------------+------------------------------+
| 节点凭据               | Agent Bearer Token (256-bit)      | 仅绑定节点上报; 吊销/替换即清  |
|                       | (本地 state/identity.json)         | 运行身份与探测缓存            |
+-----------------------+-----------------------------------+------------------------------+
```

- **管理员与 TOTP**：所有管理员等权且至少保留一名；开启两步验证生成 10 个一次性恢复码。若全部恢复码丢失，须停服执行 `orbitbeacon-server reset-totp`（同事务撤销该用户全部会话与 API 令牌）。
- **只读 API 令牌（`obt_`）**：仅开放 `tokenRoutes` 白名单的只读接口（节点/样本/历史/可用率/流量/探测摘要/告警/分组/服务监控读取），显式剥离备注、系统详情及 Agent 探测错误信息；默认每分钟 600 次（范围 1–100000，支持全局与单令牌覆盖，超限返回 `429 rate_limited`）。
- **静态加密与 CSP**：通知渠道凭据、对象存储凭据等由 `data_dir/secrets.key` 经 HKDF 派生用途隔离密钥做 **AES-256-GCM** 加密（`secretbox`）；HTML 启用严格 CSP、禁止 `iframe` 嵌入、API 不开放 CORS。
- **Agent IP 地理定位**：遵循 `trusted_proxies` 解析客户端 IP；`geoip_lookup: true` 时将未手填地区的公网 IP 发往 **ipinfo.io** 查询并缓存 24 小时（IP 变化重查）；公开展示优先取手动地区，可设 `geoip_lookup: false` 关闭外发查询。

## 7. 告警评估与双通道外发通知

```text
+--------------------+    每 30s 评估已启用节点    +-----------------------------+
| alerts.Evaluator   | -------------------------> | Main DB 事务提交             |
| (滞回计时在内存;    |                            |  ├── alert_events           |
|  已触发事件持久化)  |                            |  ├── inbox (共享通知/独立已读)|
+--------------------+                            |  └── notification_deliveries|
                                                  +--------------+--------------+
                                                                 | 提交后 Wake()
                                                                 v
+--------------------+    HA 控制库独立队列        +-----------------------------+
| 存储故障控制 Outbox | -------------------------> | notify.Worker (4 发送槽)     |
| (StoragePayload +  |                            |  ├── 每通道 20/min 限流      |
|  加密发送快照)      |                            |  ├── 退避: 1m -> 5m -> 15m -> 1h (≤5次)
+--------------------+                            |  └── pending>=100 自动合并   |
                                                  +--------------+--------------+
                                                                 |
                                                                 v
                                            Webhook / SMTP / Telegram / 飞书 /
                                            钉钉 / 企业微信 / Bark / ntfy
```

- **特殊规则**：`traffic_quota_percent`（阈值 `(0, 1000]`）按节点计费日批量快照评估，离线不中断评估；`metric_status=disabled` 可触发主机指标告警恢复；`probes_down` 无结果视为关闭，任一结果为 `pending` 时不产值。
- **双 Business/Control Outbox 隔离**：当配置 MySQL 主备时，存储故障通知写入本地控制库独立 Outbox，并使用独立用途隔离密钥加密的 `StoragePayload` 凭据快照，确保双主库失联时仍能外发告警。
- **可靠性说明**：外发通知属于尽力投递（可能延迟、洪泛合并或在重试耗尽后丢弃），不可替代独立高可用告警基础设施。

## 8. 额外指标与数据保留策略

### 8.1 数据保留周期（每小时自动分批清理）

| 数据类别 | 保留规则 |
| --- | --- |
| **节点指标历史** (`metrics.db` / 历史库) | `1m` 粒度 48 小时；`5m` 粒度 14 天；`1h` 粒度 90 天（每节点最多 16 个分盘路径，总序列上限 29,400） |
| **服务监控历史** (`service_check_buckets`) | `5m` 桶保留 30 天 |
| **节点流量** | 小时桶保留 35 天（过期整日自动汇总入日表）；日汇总保留 400 天 |
| **探测结果与小时统计** | 7 天 |
| **审计 / 已恢复告警 / 站内通知 / 终态任务与归档密码** | 90 天（告警自恢复时间起算） |
| **外发投递记录** | 已成功/失败记录保留 30 天（`pending` 不受此规则删除） |
| **手动导出文件 / 注册密钥** | 导出产物 24 小时；过期密钥额外留档 24 小时 |
| **已删除节点墓碑** (`node_deletions`) | 删除小时 + 90 天 + 1 小时（供历史域安全清理孤儿数据） |

### 8.2 额外主机指标（Linux Agent）

Agent 另采集以下三组可空指标（以 7 条标量序列保存，不增来源元数据；本地关闭时上报 `metric_status=disabled`）：
- **磁盘 IO**：仅汇总 `/sys/block/<name>/device` 存在的物理整盘读写速率与最高忙碌率。
- **PSI**：`some avg60`（CPU / 内存 / IO）。
- **温度**：`(0, 150] °C` 内最高传感器温度，每分钟独立后台任务刷新，缓存超 3 分钟丢弃。

## 9. 容量参考、压测与 Prometheus 指标

### 9.1 单机参考实测

2026-11 实测环境：fsync p50 = 25ms 慢盘、每节点 2 磁盘 / 2 网卡 / 3 探测、10s 上报、持续 5 分钟（非性能承诺，上限受磁盘决定）：

| 模拟节点数 | 上报分布 | 成功率 | 观测备注 |
| --- | --- | --- | --- |
| `200` | 均匀分布 | `100%` | 延迟 p95 = `35ms` |
| `400` | 均匀分布 | `99.17%` | 拒绝全部集中在首 10 秒首次落库波峰，之后为 0 |
| `200` | 同步突发 | `96.62%` | 拒绝主要发生在首 20 秒 |

### 9.2 压测与 Prometheus 导出

- **开发压测工具（`orbitbeacon-load`）**：先从服务端签发 N 个一次性分组部署密钥存入文件，按节点消费：
  ```sh
  go run ./cmd/orbitbeacon-load \
    -url http://127.0.0.1:8080 -tickets-file /path/to/tickets \
    -nodes 200 -interval 10s -duration 5m -jitter 4900ms -disks 2 -networks 2 -probes 3
  ```
- **Prometheus 独立监听（`metrics_listen`）**：主监听不暴露指标端口，需绑定回环或内网地址：
  - `GET /metrics`：连接池、写队列深度、History flush 延迟与 WAL 状态等服务端指标。
  - `GET /metrics/nodes`：无认证导出节点实时 Gauge（单节点受协议上限 8 磁盘 / 8 网卡约束，单次最多 67 条序列）。
