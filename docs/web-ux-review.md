# Web 体验评审与改进清单

评审日期 2026-11-10，基于 `develop`（21b1a0f）。本文只列问题与建议，未改动任何代码；每项带编号，供逐条评审、取舍后执行。

## 范围与方法

- 本地启动服务器（SQLite），用 `orbitbeacon-load` 模拟 12 个在线节点，另建 2 个待注册节点、3 个分组、4 条告警规则（触发 24 条告警）、1 条公告、9 个公开节点。
- 用 Chromium 走查中文界面：登录、概览、节点列表、节点详情 7 个页签、告警、设置 6 个页签、数据管理、命令面板、站内通知、添加节点、状态页；视口 1440、1100、390，浅色与暗色。
- 未覆盖：英文界面的文案长度、离线/已过期/禁用状态的呈现、200 节点规模、Safari 与 Firefox、通知通道与备份计划的编辑对话框、两步验证流程。

优先级：**P0** 可见缺陷；**P1** 明显降低学习或操作成本；**P2** 视觉与细节打磨。工作量：S（半天内）、M（1–2 天）、L（需要拆分）。路径相对 `web/src/`。

## 总体结论

基础扎实：设计变量完整，暗色、焦点、实时更新、草稿保护和无障碍都已到位，状态页的完成度最高。主要差距集中在三处，按收益排序：

1. **数据密度与可读性。** 节点列表每行折成两行，1440×900 只能看到 9 个节点；节点详情的“最新样本”是纯文字，读数要逐字看。
2. **信息架构。** 侧栏把页面、工具和设置混排；“数据管理”与“设置 → 数据操作”分在两处；节点详情 7 个页签里混有一次性操作。
3. **一致性。** 同一时间有三种写法，表格有两种容器样式，“刷新”按钮和“实时”徽标并存。

建议先做 P0 全部，再做 N-01～N-04、D-01、D-02、A-01、I-01，这几项覆盖了每天最常用的路径。
